# CURRENT SYSTEM PROMPT — 624Voice Speed-to-Lead Orchestrator

## About This File

This is a **representative sample** of the assembled orchestrator instructions for a scheduling-stage turn. The actual prompt varies per turn based on stage, task, knownFacts, and flow.

**Do not treat this as a static prompt file.** It is generated at runtime.

---

## Prompt Source Files

| File | Function | Content |
|------|----------|---------|
| `src/server/speed2Lead/prompts.ts` | `buildOrchestratorInstructions()` | Main assembly + repair builders |
| `src/server/speed2Lead/businessContext.ts` | `businessContextForPrompt()`, `allowedFactsForPrompt()`, `outcomeBridgeContextForPrompt()` | Product facts, bridge guidance |

| `src/server/speed2Lead/discoveryProgress.ts` | `normalizeDiscoveryFacts()` | knownFacts inputs |

**No external .md prompt files.** OpenAI Responses API uses the `instructions` field.

## Code-Owned Rules (Intentionally NOT in Prompt)

These behaviors are deterministic and must NOT be added back to prompt:

- Conversation stage transitions
- Discovery count (max 2) and phase advancement
- Meeting interest confirmation logic
- Scheduling entry legality
- All scheduling state parsing and mutation
- Date/time/daypart/exact/negation/broadening semantics
- Provider queries, slot filtering, booking
- Authoritative scheduling SMS (availability, confirmation, failures)
- Calendar link fallback eligibility
- URL classification (BOOKED_MEETING_LINK vs fallback)
- Meet URL persistence
- Reminder timing
- Outbound guardrails (question count, fake async, pricing, etc.)

---

## Repair Prompts (Separate, On Retry)

Built by `buildRepairInstructions()` and variants in `prompts.ts`:
- One-question repair
- Bridge repair (no day/time in bridge)
- Terminology repair (no "AI bots")
- Unsupported product claim repair

These append to instructions on guardrail failure retry loops.

## Other Stage Examples (task varies)

| Stage | task | taskGuidance summary |
|-------|------|---------------------|
| Report reaction | `acknowledge_report_reaction_and_ask_one_operational_question` | Acknowledge ROI reaction, one diagnostic question |
| Diagnostic | `ask_one_operational_followup` | One follow-up if relevance unclear |
| Bridge | `ask_conditional_meeting_bridge` | Pain → consequence → outcome → 25-min ask, no day/time |
| FAQ | `answer_customer_question` | Answer using allowedFacts, no calendar/booking |
| Scheduling | `brief_active_conversation` | Brief reply only, no scheduling questions |

Scheduling SMS is never LLM-generated — it comes from `processSchedulingTurn()` via `resolveAuthoritativeSchedulingReply()`.
